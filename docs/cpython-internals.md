# CPython internals the walker relies on

`heapspy-reader::cpython` reads CPython's private data structures out of a
memory image. This page lists every layout it depends on, per version, and
where each number comes from. The code is in
`crates/heapspy-reader/src/cpython/` (`offsets.rs` holds the tables).

Scope: CPython **3.12, 3.13, 3.14**, default (GIL) build, 64-bit
little-endian (x86_64, aarch64). Free-threaded (`Py_GIL_DISABLED`) and debug
(`Py_DEBUG`) builds change object headers and are refused with
`Error::UnsupportedPython`.

## Where the numbers come from

The tables were generated by compiling a small C program against each
interpreter's internal headers (`Py_BUILD_CORE`, `internal/pycore_*.h`) and
printing `offsetof` / `sizeof`:

| version | interpreter used | build |
|---|---|---|
| 3.12.3 | `/usr/bin/python3.12` (Ubuntu) | static executable |
| 3.13.18 | `/usr/local/bin/python3.13` | static executable |
| 3.14.6 | `uv python install 3.14` | `libpython3.14.so` |

Struct layouts do not change within a minor release, so one table per minor
version is enough. On 3.13+, the start of `_PyRuntime` is `_Py_DebugOffsets`
(cookie `xdebugpy`, then `PY_VERSION_HEX`, then `free_threaded`, then struct
offsets written by the target's own compiler). The walker reads it and lets
it override the runtime, interpreter, thread, frame, code, type, dict and str
offsets it covers. The layout of `_Py_DebugOffsets` itself is per minor
version (all fields are `uint64_t`, so it is the same on every OS).

**Windows x64** is LLP64: C `long` is 4 bytes. Of the fields used here only
`PyThreadState.thread_id` and `.native_thread_id` (`unsigned long`) move.
`tp_flags` is also `unsigned long`, but the next field is a pointer, so its
offset is the same; the walker reads it as 32 bits. On 3.12 (no debug offsets)
the table subtracts 4 from `native_thread_id`; on 3.13+ the debug offsets
supply it. The 3.12 Windows numbers are derived, not measured.

## Finding the runtime

1. Pick the module: `libpython3.*.so*`, then `python3XY.dll`, then the main
   executable (`symbols::find_python_module`); fall back to every module.
2. Resolve `_PyRuntime` (dynamic symbol / PE export).
3. Version: the exported `const unsigned long Py_Version = PY_VERSION_HEX`
   (3.11+), read as 32 bits; else `_Py_DebugOffsets.version`.
4. Build flags: `t` / `d` ABI suffix in the module name (`libpython3.13t.so`,
   `python313t_d.dll`), `_Py_DebugOffsets.free_threaded`, and the presence of
   `_Py_NegativeRefcount` (only exported by `Py_REF_DEBUG` builds).

(`_PyCFrame.current_frame` at 0); 3.13+ has `tstate->current_frame`.

Linux and Windows, so roots match `ThreadInfo::tid` without reading TLS.

## GC lists

`struct _gc_runtime_state` (at `interp + gc`):

```c
PyObject *trash_delete_later; int trash_delete_nesting; int enabled; int debug;
struct gc_generation generations[3];   /* { PyGC_Head head; int threshold; int count; } = 24 bytes */
PyGC_Head *generation0;                 /* 3.12, 3.13 only */
struct gc_generation permanent_generation;
```

| list head offset | 3.12 | 3.13 | 3.14 |
|---|---:|---:|---:|
| `generations[0..3]` | 24, 48, 72 | 24, 48, 72 | 24, 48, 72 |
| `permanent_generation` | 104 | 104 | 96 |

3.14's default build still has `generations[3]` (the incremental collector's
`young` / `old[2]` exist only in the free-threaded build) but dropped
`generation0`, so the permanent generation moved to 96.

`PyGC_Head` is 16 bytes (`_gc_next`, `_gc_prev`) right before the object.
The low bits of both words carry flags (`NEXT_MASK_UNREACHABLE`, the
collecting / finalized bits), so the walker masks the low 3 bits. Each list
is circular through its sentinel head. The walk is bounded (mapped bytes / 32
steps) and uses Brent's cycle detection; a list that does not return to its
head, or a link to unreadable memory, ends that list and marks the snapshot
`truncated`. `_gc_prev` is not checked, because during a collection it holds
reference counts.

Static objects (static types, small ints, `None`) are not on any list and are
only recorded when something references them; static type objects are never
recorded (they belong to the interpreter image, not the heap).

## Object header and types

`PyObject`: `ob_refcnt` at 0, `ob_type` at 8; `PyVarObject.ob_size` at 16.
Immortal objects: `(int32_t)ob_refcnt < 0` (3.12 `0xFFFFFFFF`, 3.13+ bit 31).

`PyTypeObject` / `PyHeapTypeObject` (same in all three versions):

| field | offset |
|---|---:|
| `tp_name` | 24 |
| `tp_basicsize`, `tp_itemsize` | 32, 40 |
| `tp_flags` | 168 |
| `tp_base` | 256 |
| `tp_dict` | 264 |
| `tp_dictoffset` | 288 |
| `tp_bases`, `tp_mro` | 336, 344 |
| `ht_name`, `ht_slots`, `ht_qualname`, `ht_cached_keys`, `ht_module` | 856, 864, 872, 880, 888 |

Type names: heap types use `ht_qualname` and `tp_dict['__module__']`; static
types split `tp_name` at the last dot (`collections.OrderedDict`), with
`builtins` when there is none. The kind of an object (dict, list, ...) comes
from the `Py_TPFLAGS_*_SUBCLASS` bits, else from the `tp_name` of its nearest
static base, so heap subclasses of builtins get both the builtin's edges and
instance edges.

`__slots__`: a heap type's `PyMemberDef` array follows the type object at
`Py_TYPE(type)->tp_basicsize`, `Py_SIZE(type)` entries of 40 bytes
(`name` 0, `type` 8, `offset` 16). Entries of type `Py_T_OBJECT_EX` (16) or
`T_OBJECT` (6) become `Attr(name)` edges. The walker collects them along the
`tp_base` chain while the bases are heap types.

## Instance attributes

`Py_TPFLAGS_MANAGED_DICT` (1<<4) types keep a pointer word at `obj - 24`
(`((PyObject **)obj)[-3]`, the word just before the 16-byte GC header).

- **3.12** `PyDictOrValues`: if the low bit is set the word is
  `values - 1`, a separately allocated `PyDictValues` (`PyObject *values[]`)
  indexed like the entries of the type's `ht_cached_keys`; otherwise it is the
  materialized `__dict__`.
- **3.13 / 3.14** `PyManagedDictPointer`: the dict, or NULL. With
  `Py_TPFLAGS_INLINE_VALUES` (1<<2) the values live inline at
  `obj + tp_basicsize`: `PyDictValues { uint8 capacity, size, embedded, valid; ...; PyObject *values[] }`,
  values at +8. `valid == 0` means they moved into a dict.

Without a dict, values become `Attr(name)` edges, names from the shared keys.
With a dict, the instance has `Attr("__dict__")` and the dict has
`DictValue` edges. Types with `tp_dictoffset > 0` keep the dict pointer there.

## Dicts

`PyDictObject`: `ma_used` 16, `ma_keys` 32, `ma_values` 40 (48 bytes).

`PyDictKeysObject` (32-byte header): `dk_refcnt` 0, `dk_log2_size` u8 at 8,
`dk_log2_index_bytes` u8 at 9, `dk_kind` u8 at 10, `dk_usable` 16,
`dk_nentries` 24, `dk_indices` at 32. Entries start at
`32 + (1 << dk_log2_index_bytes)`. `dk_kind` 0 (general) entries are
`{hash, key, value}` (24 bytes); 1 (unicode) and 2 (split) are
`{key, value}` (16 bytes). Split tables keep values in `ma_values`
(`PyDictValues`, values at +0 on 3.12, +8 on 3.13+).

`getsizeof(dict)` = 48 + (split: `(dk_usable + dk_nentries) * 8`) +
(if `dk_refcnt == 1`: `32 + (1 << log2_index_bytes) + ((size*2)/3) * entry_size`),
plus the 16-byte GC header. Shared split keys are attributed to the type
(`type.__sizeof__` adds `ht_cached_keys`).

Frame owners: 0 thread, 1 generator, 2 frame object; 3 and above are C-stack
shims (3.12, 3.13) or interpreter-owned frames (3.14), which the walker skips.
A generator's embedded frame is live while `gi_frame_state < 1`
(`FRAME_COMPLETED` is 1 in all three versions).

On 3.14 frame slots and `f_executable` are `_PyStackRef`: tagged pointers.
`bits & 3 == 3` is a tagged int (not an object); otherwise the object is
`bits & ~3`.

Local names come from `co_localsplusnames[i]` for `i < co_nlocalsplus`;
slots from `co_nlocalsplus` up to the stack top are value-stack entries.

## Shallow sizes

`shallow_size` matches `sys.getsizeof` (verified against all three
interpreters for int, float, str of each kind, bytes, bytearray, list, tuple,
dict, set, frozenset, slotted and dict-subclass instances, function, cell,
module, class, code, generator, bound method and frame):

- pre-header: 16 for `Py_TPFLAGS_HAVE_GC`, plus 16 for managed dict /
  weakref types (`_PyType_PreHeaderSize`);
- default: `tp_basicsize + |ob_size| * tp_itemsize`; code objects round up
  to 8 (`_PyObject_VAR_SIZE`);
- int: `24 + 4 * max(ndigits, 1)`; str: header + `(len + 1) * kind`, plus a
  separate UTF-8 buffer if any;
- list: `+ allocated * 8`; set: `+ (mask + 1) * 16` when the table is not the
  small table; bytearray: `+ ob_alloc`; dict: see above;
- generator, frame: fixed part + frame header + `(co_framesize - header words) * 8`;
- heap type: `tp_basicsize` of the metatype + `ht_cached_keys` size.

One deliberate difference: an instance whose attributes are in values (no
materialized dict) also counts the values array: on 3.12 the separate
`PyDictValues` allocation (`n * 8` + order prefix), on 3.13+ the inline values
(`_PyInlineValuesSize`). `getsizeof` omits them, but they are real memory the
instance owns, and without them retained sizes of many small objects are
understated. When a dict is materialized, the dict counts them instead (as
`getsizeof(dict)` does).

## Roots

| kind | label | object |
|---|---|---|
| `module_dict` | `sys.modules['<name>']` | each value of `interp->imports.modules` |
| `interp` | `interp sys.modules`, `interp builtins`, `interp sys` | the dicts |
| `thread_locals` | `thread <tid> dict`, `thread <tid> exception` | `tstate->dict`, `tstate->current_exception` |
| `frame_local` | `frame <module>:<co_qualname> local '<name>'` | each non-null local of each frame on each thread's chain |
| `frame_local` | `frame <module>:<co_qualname> stack` | value-stack entries |
| `frame_local` | `frame <module>:<co_qualname> f_locals` | `f_locals` when it is not the globals dict |

`<module>` is the frame function's `__module__`, or the file name stem.
`f_globals` and `f_builtins` are not rooted separately: they are reachable
from `sys.modules`, and rooting them would shorten every path to a global.

## Redaction

Namespace dicts, whose `str` keys are stored as text, are found before any
object is emitted: `md_dict` of modules, `tp_dict` of types, `func_dict` of
functions, and the materialized `__dict__` of instances. Every other dict is
ordinary and its keys are redacted unless contents are captured.
